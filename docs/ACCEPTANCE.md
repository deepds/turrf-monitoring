## 2. Ручной сценарий дашборда

Десять шагов. Каждый проверяет требование, которое нельзя проверить кодом.

| № | Действие | Что должно быть видно |
|---|---|---|
| 1 | Открыть дашборд | Шапка с датой наблюдения и статусом снимка |
| 2 | «Куда ехать»: выбрать город, даты, авиа, 4★ | Четыре направления с расчётной стоимостью |
| 3 | Посмотреть строку | Транспорт, проживание и итог показаны раздельно |
| 4 | Переключить на ЖД | Подпись «Сумма двух отдельно наблюдавшихся плеч» |
| 5 | Кликнуть по цене | Детализация: медиана, минимум, выборка, уверенность |
| 6 | Вкладка «Предложения» | Включённые и исключённые, у каждого исключения причина |
| 7 | «Транспорт»: обзор → маршрут | Четыре линии → одна линия и таблица под ней |
| 8 | Выбрать историческую дату наблюдения | График перестроился, шапка показывает выбранную дату |
| 9 | «Проживание»: сменить категорию | Пять городов, одна ночь, выбранная звёздность |
| 10 | Скачать выгрузку | CSV и Excel открываются, кириллица не поломана, исключённые строки подсвечены |

Дополнительно:

* **Провалившийся снимок.** Если сегодняшний прогон `FAILED`, витрина обязана
  показать последний пригодный и сказать об этом жёлтой полосой.
* **Демонстрационные данные.** Синтетический снимок обязан быть помечен
  красной полосой и не выбираться как «последний опубликованный».

## 3. Ручная сверка контрольных цен

Главная проверка приёмки. Выполняется человеком, автоматизации не подлежит.

1. Открыть шесть опубликованных цен: две ЖД, две авиа, две проживания.
2. В детализации взять по одному включённому предложению.
3. Открыть ссылку «проверить на сайте».
4. Сверить цену **до рубля**.

**Расхождение с сайтом означает ошибку не в цене, а в составе выборки.**
Парсинг совпадает с сайтом до рубля; ошибаются правила отбора. Смотреть надо
исключённые предложения и причины исключения.

Каждое подтверждённое расхождение превращается в regression-тест в тот же
день.

## 4. Критерии Go / No-Go

### Блокирующие

- [ ] Полная матрица 15 840 наблюдений строится и собирается
- [ ] Снимок публикуется не позднее 10:00 MSK
- [ ] `NO_MARKET` отличим от технического сбоя на витрине
- [ ] Каждая опубликованная цифра раскрывается до исходного предложения
- [ ] Golden Dataset проходит
- [ ] PostgreSQL integration tests проходят
- [ ] Шесть контрольных цен сверены с сайтами до рубля
- [ ] Дашборд не обращается к внешним источникам

### Не блокирующие, но обязательные к фиксации

- [ ] Soak-прогон многочасовой нагрузки проведён
- [ ] Замер РЖД под нагрузкой выполнен
- [ ] Несколько последовательных суточных снимков собраны
- [ ] Восстановление после рестарта PostgreSQL проверено

## 6. Что осталось незакрытым

Названо прямо, чтобы решение принималось с открытыми глазами.

| Пробел | Риск | Чем компенсируется |
|---|---|---|
| Soak-прогон не проведён | Поведение источника на многочасовой нагрузке неизвестно | Окна расписания с двукратным запасом, размыкатель, досбор |
| РЖД не измерен под нагрузкой | Оценка пропускной способности приблизительна | Консервативные значения одновременности |
| Латентность источника нестабильна (разброс в 5 раз) | Риск выхода за SLA | 14 часов запаса после 10:00 |
| Frontend E2E не автоматизирован | Регрессия интерфейса ловится глазами | Ручной сценарий выше, проверка типов в CI |
| Ручная сверка цен не проведена | Главная проверка корректности | Процедура описана, дип-линки выводятся |
