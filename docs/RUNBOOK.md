# RUNBOOK

Эксплуатация системы ежедневного мониторинга. Документ отвечает на вопросы
дежурного: что запустить, куда смотреть, что делать, когда ночью не собралось.

Смежное: [COLLECTION_RELIABILITY.md](../COLLECTION_RELIABILITY.md) — почему
эти правила именно такие; [ADMIN_GUIDE.md](ADMIN_GUIDE.md) — административные
экраны и операции.

---

## 1. Где что работает

| Компонент | Адрес | Роль |
|---|---|---|
| Дашборд | `http://<узел>:8090` | Витрина |
| API | `http://<узел>:8091/docs` | REST v1 и OpenAPI |
| PostgreSQL | `<узел>:55432` | Источник истины |
| Redis | `<узел>:56379` | Брокер Celery |

Контейнеры: `api`, `worker`, `worker-service`, `beat`, `ui`, `postgres`,
`redis`, `autoheal`.

**Сбор обязан выполняться на узле, откуда доступен РЖД.** Проверено:
`ticket.rzd.ru` отвечает с узла кластера за 0,2 с и недоступен с рабочих
станций. Прогон, запущенный не там, молча даст одноисточниковую железную
дорогу.

## 2. Ежедневное расписание

| Время MSK | Что | Окно |
|---|---|---|
| 00:30 | План на новый день горизонта | 10 мин |
| 01:00 | ЖД, оба источника | 1 ч |
| 02:00 | Авиа, круговой тариф | 3 ч |
| 05:00 | Проживание | 3 ч |
| 08:00 | Досбор дыр | 1 ч |
| 09:00 | Расчёт и витрина | 30 мин |
| 09:30 | Ворота качества и публикация | — |
| 10:00 | Суточная сводка качества | — |

К 10:00 всё закончено, дальше четырнадцать часов запаса: если ночь прошла
плохо, есть время повторить до следующих суток, а не ждать их.

## 3. Команды

Все команды выполняются из каталога развёртывания.

```bash
docker compose ps
docker compose logs -f worker --tail 200
```

### Проверить источники перед прогоном

```bash
docker compose exec api python -m tmo.cli check-sources
```

Единственная команда, которая ходит в сеть. Если РЖД отвечает `error` —
прогон даст одноисточниковую железную дорогу; чинить до сбора.

### Запустить суточный цикл руками

```bash
docker compose exec api python -m tmo.cli collect --snapshot-date today
```

### Досбор дыр

```bash
docker compose exec worker-service celery -A tmo.tasks.celery_app:celery_app \
  call tmo.recover_snapshot
```

Досбор идёт с солью в ключе идемпотентности: повторный запуск делает новую
попытку, а не возвращает прежний результат.

### Пересчёт другой методикой

```bash
docker compose exec api python -m tmo.cli recalculate --snapshot-date 2026-08-07 --profile baseline_v1
```

Создаёт **новый** `CalculationRun`. Прежний остаётся неизменным: на него
ссылаются уже показанные цифры.

### Покрытие снимка

```bash
docker compose exec api python -m tmo.cli coverage --snapshot-date today
```

### Проверка живости сбора

```bash
docker compose exec worker python -m tmo.tasks.health; echo "код возврата: $?"
```

Проверка спрашивает не «отвечаешь ли ты», а **разбирается ли очередь**.
Пустая очередь считается здоровьем: разбирать нечего, молчание законно.

### Golden Dataset

```bash
docker compose exec api python -m tmo.cli golden
```

## 4. Чек-лист: сбор не идёт

1. **Живы ли контейнеры и что говорит проверка живости**
   ```bash
   docker compose ps
   docker compose exec worker python -m tmo.tasks.health
   ```
2. **Есть ли задачи в очереди**
   ```bash
   docker compose exec redis redis-cli llen collect
   docker compose exec redis redis-cli llen maintenance
   ```
   Пустая очередь при отсутствии данных означает, что не сработало
   расписание, а не сбор.
3. **Что выполняется в СУБД прямо сейчас**
   ```bash
   docker compose exec postgres psql -U tmo -d tmo -c \
     "SELECT pid, state, now()-query_start AS dur, left(query,60) FROM pg_stat_activity WHERE datname='tmo' AND state <> 'idle' ORDER BY query_start;"
   ```
   Запрос в `active` дольше минуты почти всегда означает отсутствующий индекс.
   `idle in transaction` дольше нескольких минут — сеть попала внутрь
   транзакции; это дефект, а не нагрузка.
4. **Что отвечали источники**
   ```bash
   docker compose exec postgres psql -U tmo -d tmo -c \
     "SELECT source_code, outcome, count(*) FROM source_attempts WHERE snapshot_id = (SELECT max(id) FROM market_snapshots) GROUP BY 1,2 ORDER BY 3 DESC;"
   ```
   `CIRCUIT_OPEN` означает, что мы сами перестали спрашивать.
5. **Сколько потеряно** — экран «Покрытие и качество» либо
   `python -m tmo.cli coverage`.
6. **Догнать** — досбор без ожидания расписания.

## 5. Что означают исходы источника

| Исход | Что произошло | Дыра? |
|---|---|---|
| `SUCCESS` | Полная выдача | нет |
| `PARTIAL` | Выдача обрезана: потолок страниц или бюджет времени | нет |
| `NO_MARKET` | Источник ответил, предложений нет | **нет** — это ответ о рынке |
| `TIMEOUT` | Источник не ответил вовремя | да |
| `RATE_LIMITED` | Источник ограничил темп | да |
| `SCHEMA_ERROR` | Форма ответа не та | да, но досбор бесполезен до правки коннектора |
| `TRANSPORT_ERROR` | Сеть или 5xx | да |
| `CIRCUIT_OPEN` | Мы сами перестали спрашивать | да, пройдёт за 900 с |
| `BUDGET_EXHAUSTED` | Мягкий бюджет пачки исчерпан | да |
| `FAILED` | Прочее | да |

**Самара — Казань по ЖД всегда `NO_MARKET / NO_DIRECT_SERVICE`.** Прямого
сообщения не существует; добирать его каждую ночь значило бы тратить
обращения впустую.

## 6. Типовые инциденты

### Снимок опубликован как `DEGRADED`

Смотреть `publication_notes` на экране «Покрытие и качество». Обычные причины:
покрытие ниже 98 % по одному из семейств; отказы источника в выборке.
Действие: досбор, затем `finalize` — снимок пересчитает статус.

### Снимок `FAILED`

Витрина показывает **последний пригодный** снимок и говорит об этом баннером.
Это не авария витрины, это защита: подменять вчерашние наблюдения сегодняшними
запрещено. Действие: разобрать причину по `publication_notes`, исправить,
запустить `collect` повторно — появится новый `attempt_no`.

### Воркер числится здоровым, но очередь не разбирается

`restart: unless-stopped` поднимает **упавший** контейнер; зависший не падает.
Три линии защиты: сторож `watch_collection_progress` каждые пять минут,
healthcheck по прогрессу, `autoheal`. Если ни одна не сработала:

```bash
docker compose restart worker
```

Задачи с подтверждением после выполнения возвращаются в очередь, а не
теряются.

### Источник ответил 503 и открылся размыкатель

Мы превысили безопасный темп. Проверить `TMO_TUTU_CONCURRENCY` (рабочая
точка — 8) и `rate_limit_per_minute` в `tmo/catalog/data/sources.yaml`.
Размыкатель остывает за 900 с, досбор в 08:00 подберёт пропущенное.

### `pypi.org` недоступен при сборке образа

Проверено на узле кластера: `pypi.org` закрыт, `files.pythonhosted.org`
открыт. Задать зеркало в `.env`:

```bash
TMO_PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple
TMO_PIP_TRUSTED_HOST=mirrors.aliyun.com
```

Зеркало — свойство сети развёртывания, поэтому в образ оно не зашивается.

## 7. Удаление данных: три способа потратить час впустую

Операции редкие, поэтому дефекты в них доживают до объёмов, на которых
становятся непроходимыми.

1. **`IN` со списком из тысяч идентификаторов не работает.** Планировщик
   получает тысячи констант вместо отношения. Отбор задаётся **подзапросом**.
2. **Внешний ключ без индекса делает удаление квадратичным.** Порядок:
   **сначала дети, потом родители**.
3. **`docker stop` не останавливает запрос.** Он убивает клиента, серверный
   процесс продолжает начатое. Смотреть надо в `pg_stat_activity`.
4. **Обрыв SSH оставляет живую транзакцию.** Долгие операции запускаются
   отвязанными от сессии (`docker compose run -d`), а не через `nohup` поверх
   `ssh`.

Ретеншен тел сырых ответов — 45 суток, задача `tmo.purge_raw`. **Метаданные,
Offers и метрики не удаляются никогда:** без них опубликованную цифру нельзя
объяснить.

## 8. Резервное копирование

```bash
docker compose exec -T postgres pg_dump -U tmo -Fc tmo > tmo-$(date +%F).dump
docker run --rm -v tmo_raw_storage:/data -v "$PWD":/backup alpine \
  tar czf /backup/raw-$(date +%F).tar.gz -C /data .
```

Восстановление проверяется на копии, а не на бою.

## 9. Ручная сверка контрольных цен

Процедура приёмки и регулярной проверки. Выполняется человеком.

1. Открыть дашборд, выбрать любую опубликованную цену.
2. В детализации цены взять шесть включённых предложений.
3. По ссылке «проверить на сайте» открыть выдачу источника.
4. Сверить цену **до рубля**.
5. Расхождение означает ошибку не в цене, а в **составе выборки**: смотреть
   исключённые предложения и причины исключения.
6. Каждое подтверждённое расхождение превращается в regression-тест.
