# Data Contract

Описание сущностей, полей и инвариантов. Документ отвечает на вопрос «что
означает эта колонка и на что нельзя опираться».

---

## 1. Инварианты, которые держит вся модель

1. Наблюдение неизменяемо: повторный сбор за ту же дату создаёт новый
   `attempt_no`.
2. `CalculationRun` неизменяем: пересчёт создаёт новый.
3. У каждой опубликованной метрики есть провенанс до сырого ответа.
4. `NO_MARKET ≠ технический сбой`.
5. Свежесть считается от `fetched_at`, не от `snapshot_date`.
6. Исключённое предложение не удаляется и имеет причину исключения.
7. Частичный результат сохраняется и помечается.
8. Молчаливый пропуск источника невозможен: у каждой попытки конечная запись.
9. Цена в базе всегда положительна (ограничение уровня СУБД).
10. Пороги и правила живут в версионируемом профиле, не в коде.

## 2. Наблюдение

### `market_snapshots`

| Поле | Смысл |
|---|---|
| `snapshot_date` | Бизнес-идентификатор наблюдения — календарная дата по МСК |
| `attempt_no` | Номер попытки за дату; повтор не переписывает предыдущую |
| `status` | `PLANNING → COLLECTING → RECOVERING → CALCULATING → READY / DEGRADED / FAILED` |
| `is_synthetic` | Снимок собран воспроизведением; витриной рынка не является |
| `primary_collection_finished_at`, `recovery_finished_at`, `published_at` | Реперные точки цикла |
| `coverage_*` | Доля завершённых наблюдений: всего и по семействам |
| `publication_notes` | Почему `DEGRADED` или `FAILED`; пусто у `READY` |

**Не опираться на:** `snapshot_date` как на время получения данных. Для
свежести есть `fetched_at`.

### `collection_plans`

Агрегаты плана и `plan_digest` — отпечаток состава. Одинаковые дата, справочник
и горизонт обязаны давать одинаковый отпечаток.

### `collection_jobs`

Логическое наблюдение рынка, независимое от коннектора.

| Поле | Смысл |
|---|---|
| `job_key` | Что наблюдается **внутри снимка**, с абсолютными датами |
| `series_key` | Тот же ряд **между снимками**: даты заменены смещением от D |
| `status` | `PLANNED / DISPATCHED / RUNNING / SUCCESS / PARTIAL / NO_MARKET / FAILED` |
| `no_market_reason` | `NO_DIRECT_SERVICE / ALL_FILTERED_OUT / EMPTY_RESPONSE` |
| `is_partial` | Выдача хотя бы одного источника обрезана |
| `day_offset` | Смещение служебной даты от даты снимка, 1..30 — ось графиков |
| `fetched_at` | Самое раннее фактическое получение по источникам |

**`NO_MARKET` — завершённое наблюдение.** Оно входит в `completed`, не входит в
дыры и не вызывает бесконечный досбор.

### `source_attempts`

Одно обращение к одному источнику по одному наблюдению.

| Поле | Смысл |
|---|---|
| `execution_scope` | `PRIMARY / RECOVERY / …` — входит в ключ идемпотентности |
| `idempotency_key` | Снимок + семейство + наблюдение + источник + область + соль |
| `outcome` | `SUCCESS / PARTIAL / NO_MARKET / TIMEOUT / RATE_LIMITED / SCHEMA_ERROR / TRANSPORT_ERROR / CIRCUIT_OPEN / BUDGET_EXHAUSTED / FAILED` |
| `requested_at` / `fetched_at` | Когда спросили и когда получили |
| `pages_read`, `total_matched` | Прочитано страниц и сколько объектов насчитал источник |
| `is_partial`, `partial_reason` | `SOURCE_PAGE_CAP` или `TIME_BUDGET` |

**`total_matched = NULL` означает «источник не сообщил»** и отличается от нуля.

### `raw_responses`

Метаданные исходного ответа. Тело — в файловом хранилище, `storage_ref` ведёт к
нему, `payload_sha256` позволяет обнаружить подмену задним числом.

Неизменяем. Хранится 45 суток, затем удаляется **только тело**.

### `offers`

Нормализованное предложение.

| Поле | Смысл |
|---|---|
| `price` | Цена, приведённая к единице методики |
| `source_price` | Что прислал источник до приведения |
| `price_basis` | В какой единице считать `price` |
| `fingerprint` | Отпечаток строки источника: различает тарифные варианты |
| `equivalence_key` | Физический объект рынка; **включает код источника** |
| `validation_flags` | Замеченные несоответствия; **не удаляют предложение** |

Единицы `price` по семействам:

```text
RAIL   ₽ за одно место в одну сторону
AIR    ₽ за одного пассажира за круговую поездку
HOTEL  ₽ за номер за весь период проживания
```

**Не опираться на:** `equivalence_key` как на идентификатор рейса в целом — он
включает источник, поэтому один поезд у двух продавцов даёт два ключа. Это
намеренно: два наблюдения разных продавцов, а не дубликат.

## 3. Расчёт

### `calculation_runs`

`methodology_version` + `is_active`. Активный расчёт снимка ровно один; прежние
остаются для сравнения версий.

### `calculated_metrics`

| Поле | Смысл |
|---|---|
| `metric_type` | `RAIL_LEG / AIR_ROUND_TRIP / HOTEL_STAY / HOTEL_NIGHT` |
| `median_price` | Главная пользовательская цена |
| `min_price` | «от» |
| `offers_count` | После отбора и схлопывания тарифной сетки |
| `offers_excluded` | Сколько не вошло |
| `sources_count` | Сколько источников подтвердили выборку |
| `per_source` | Медиана по каждому источнику отдельно |
| `is_no_market` + `no_market_reason` | Метрика есть, цены в ней нет, причина указана |
| `warning_codes` | Что не так с выборкой |
| `fetched_at` | Свежесть данных, на которых посчитана метрика |

**Не опираться на:** отсутствие строки как на «нет рынка». Отсутствие рынка —
это строка с `is_no_market = true`. Отсутствие строки означает, что наблюдение
не завершилось, и это видно в покрытии.

### `metric_offer_links`

Решение методики по каждому предложению.

```text
is_included = true   → contributed_price заполнена
is_included = false  → exclusion_reason обязателен
```

Причины исключения перечислены в `/api/v1/reference/dictionary` вместе с
человеческой расшифровкой.

### `trip_cost_mart`

Витрина «Куда ехать». `transport_metric_ids` и `accommodation_metric_id` ведут
провенанс поездки к составляющим; `missing_components` перечисляет, чего не
хватило, если строка неполная.

## 4. Контракт REST v1

| Эндпоинт | Отдаёт |
|---|---|
| `GET /health` | Состояние сервиса и последнего снимка |
| `GET /market-snapshots` | Доступные даты наблюдения |
| `GET /market-snapshots/latest` | Последний опубликованный снимок + сводка |
| `GET /market-snapshots/{date}` | Снимок за дату |
| `GET /showcase/origins` | Города отправления |
| `GET /showcase/trips` | Направления с расчётной стоимостью поездки |
| `GET /charts/rail` | Ряды ЖД по датам отправления |
| `GET /charts/hotels` | Ряды проживания по датам заезда |
| `GET /metrics/{id}` | Метрика целиком |
| `GET /metrics/{id}/offers` | Предложения метрики с причинами исключения |
| `GET /coverage/{date}` | Покрытие, матрица, дыры |
| `GET /exports/metrics/{id}?fmt=csv\|xlsx` | Выгрузка детализации |
| `GET /reference/cities` | Города и известные пробелы рынка |
| `GET /reference/methodology` | Активный профиль целиком |
| `GET /reference/sources` | Источники и семантика их цен |
| `GET /reference/dictionary` | Расшифровка кодов исключений и предупреждений |
| `POST /admin/snapshots/{date}/retry` | Досбор дыр (требует токен) |
| `POST /admin/snapshots/{date}/recalculate` | Пересчёт (требует токен) |

**Все величины приходят посчитанными.** Фронтенду не нужно и не разрешено
что-либо выводить: это проверяется воротами публикации.

**Контекст снимка приходит с каждым ответом витрины:** дата, статус,
`is_fallback`, `is_synthetic`, версия методики, идентификатор расчёта.

---

## 5. Совместимость

* Значения перечислений попадают в базу и в API как строки: переименование —
  это миграция данных, а не рефакторинг.
* `OFFER_SCHEMA_VERSION` пишется в каждую строку `offers`: исторические Offers,
  разобранные разными поколениями кода, различимы.
* `CONNECTOR_CONTRACT_VERSION` меняется при изменении полей `ProviderOffer`.
