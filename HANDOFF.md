## 1. Что это за система

Ежедневный мониторинг стоимости поездок между Москвой, Санкт-Петербургом,
Сочи, Самарой и Казанью на горизонте 30 будущих дней. Ночью система заново
измеряет рынок по матрице из **15 840 логических наблюдений**, сохраняет
исходные ответы источников, нормализует их, применяет версионируемую методику и
к 10:00 MSK публикует витрину, в которой любую цифру можно раскрыть до
конкретного предложения конкретного источника.

Спецификация: `C:\Users\user\Downloads\SCOPE-R.md` (SCOPE-R 1.0).

## 4. Решения, которые нельзя откатывать не подумав

| Решение | Причина |
|---|---|
| ЖД наблюдается **плечом**, не круговой поездкой | Круговое наблюдение даёт сочетания «поезд туда × поезд обратно» — набор комбинаций вместо выбора пассажира |
| Авиа — **настоящий круговой тариф** на пару дат | Сумма двух односторонних круговым тарифом не является |
| Проживание поездки — **настоящий multi-night запрос** | Умножение цены ночи на число ночей запрещено методикой |
| Причина исключения лежит в `metric_offer_links`, не в `offers` | Исключение — вывод методики; при пересчёте другой версией то же предложение может войти в выборку |
| Карта мест Туту **не используется** | Её цены предкорзинные, ниже корзины на 6–8 %; категория вагона теперь есть в поиске |
| Локальная проверка типа размещения **обязательна** | Серверный фильтр `hotel_types=['hotel']` был отправлен И подтверждён — и всё равно вернул гостевой дом и апарт-отель |
| `TotalPlaceQuantity` читается раньше `PlaceQuantity` | В живом ответе РЖД `PlaceQuantity: 0` при 182 нижних и 195 верхних местах |
| Одновременность Туту — 8 | При 12 получен `503`, размыкатель унёс 343 наблюдения из 465 |
| Сеть **вне** транзакции базы | Ожидание лимита темпа внутри транзакции держало `idle in transaction` 16 минут |
| Пакетная вставка Offers и метрик | Построчная запись через ORM стала узким местом на первом прогоне полной матрицы |
| Сбор и расчёт выполняются **на узле с базой** | Тот же расчёт с рабочей станции по локальной сети идёт в 10–20 раз дольше: 13 % CPU, остальное — ожидание сети |

## 5. Как запустить

### Локально, без сети

```bash
python -m venv .venv && .venv/Scripts/pip install -e ".[dev]"
python -m tmo.cli init-db
python -m tmo.cli demo-snapshot --horizon 5
python -m pytest -q
```

### Стек целиком

```bash
docker compose up -d --build
```

UI http://localhost:8090, API http://localhost:8091/docs.

### Боевой сбор

```bash
docker compose exec api python -m tmo.cli check-sources
docker compose exec api python -m tmo.cli collect --snapshot-date today
```

### PostgreSQL-набор тестов

```bash
TMO_TEST_DATABASE_URL=postgresql+psycopg://tmo:tmo_dev_pwd@192.168.10.67:55432/tmo pytest -m postgres
```

## 8. Известные ловушки при продолжении работы

0. **`TMO_CORS_ORIGINS` со списком через запятую роняет запуск API** на
   версиях до исправления в Phase 5: pydantic-settings разбирает значение
   list-поля как JSON до валидаторов. Закрыто аннотацией `NoDecode`.
1. **Правка `catalog/data/profiles/baseline_v1.yaml` после первого расчёта
   остановит прогон.** Так и задумано: изменение правила требует новой версии.
   Для разработки есть `TMO_ALLOW_METHODOLOGY_REREGISTER=true`, и он не
   работает, если на версию уже сослался расчёт.
2. **`alembic.ini` должен оставаться ASCII.** `configparser` читает его в
   системной кодировке; кириллица в комментариях ломает `alembic` на Windows.
3. **РЖД недоступен с рабочей станции.** Прогон, запущенный локально, даст
   одноисточниковую железную дорогу и не покажет расхождения цен.
4. **Полный расчёт по локальной сети идёт около полутора часов.** На узле с
   базой — минуты. Не пытайтесь считать полную матрицу с ноутбука.
5. **Синтетический снимок не выбирается как витрина.** `latest_published`
   отфильтровывает `is_synthetic`; для демонстрации UI показывает его через
   явный выбор даты наблюдения.
